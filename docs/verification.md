# What has been checked

All five written contracts pass full GenVM AST and SDK semantic validation. There are 98 passing direct contract tests, five passing five-validator simulator tests and 61 passing backend/UI tests. Frontend lint, TypeScript and the production build pass.

The current registry, court and escrow are finalized and wired together. Their live source bytes match local fingerprints. Separate original and corrected deployment records are preserved in deployment.json; existing indexed tenancies retain their own immutable contract addresses.

Contract regressions exercise abandoned bonds, opposing invalid departure evidence, evidence correction, retryable inconclusive rehearings, unavailable references, deterministic missing/late/empty notices, underfunded penalties, unsafe reserve funding, fixed departure dates, full agreement fingerprints and documented expenditure ceilings. Five-validator simulator tests use real SDK cross-contract reads with controlled web/model inputs and an inline sandbox shim. They validate connected recovery logic, but do not establish actual GenVM execution, live external-model agreement or recipient transfers.

A real image control pair reached consensus as pre existing condition. A separate live sandbox probe verified the 21 day deadline calculation. A tiny EVM-interface payout probe finalized successfully and increased the recipient wallet balance by exactly seven atto. Native IC messages to EOA wallets failed in the preceding candidate; that failed test remains in the smoke history. The corrected deployment completed a live lifecycle with two independent accounts: full terms acceptance, arrival acknowledgement, deposit and reserve custody, mutual early departure, competing evidence including a wrong landlord hash, an empty notice, a deterministic zero-deduction verdict and finalized settlement. Exact finalized external transfer receipts credited the tenant 1,000 atto and the landlord 2,000 atto; their balances increased by those amounts and escrow decreased by 3,000 atto. Transaction hashes, parent bindings and before/after balances are in docs/studionet-smoke.json. This proves the zero-claim payout lifecycle on actual GenVM and StudioNet simulated credits. Live time-expiry, subjective appeals and varied real-damage model consensus remain outside this smoke; adversarial recovery is covered by direct and simulator tests.

A real email code was accepted by Privy. The resulting access token was cryptographically verified, the account has an embedded Ethereum wallet, and the protected tenancy API returned its actual empty list. No fabricated account records were seeded. Desktop and mobile screenshots were reviewed in both themes. The authenticated dashboard and production candidate API also passed. Browser-only fixtures based on the actual live record verified evidence correction, immutable snapshots, post-departure reserve top-ups and expenditure/receipt inputs; no fixture records were seeded. Firefox reported no page errors or mobile overflow.

The production app uses Vercel Blob and Neon. Vercel’s visitor authentication gate is disabled for this public application. Secrets remain in ignored local files or hosting configuration. The deployment signer is absent from the application runtime.

## Dependency review

Updates removed the websocket, UUID and URI decoder advisories. The remaining audit result comes from one Zod memory exhaustion advisory in transitive dependencies used by Privy and Vercel tooling. Several parents require Zod 3. Forcing Zod 4 across those packages would change their validation APIs and has not been treated as a safe fix.

The application’s own Zod version is patched. API bodies, inventory sizes, photo bytes and request rates are bounded. External wallet login methods are disabled. The upstream dependency still requires a compatible patched release; a clean application lint result does not mean the dependency audit is clean.
